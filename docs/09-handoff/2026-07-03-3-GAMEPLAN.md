### P1.1 — Refit the calibrator on CLEAN data ⭐ (unblocks the one open question)
The v2026-07-03 calibrator is **backfill-leaked** (all 94.8K training rows graded in one 2026-01-10
batch; impossible WRs; served curve over-promises 6-20pp vs live v12). Loader is also direction-blind.
- Refit on **live-only rows** (`prediction_accuracy` 2026-01-09→present, v12 families) OR the clean
  walk-forward cache the discovery tools use.
- Add a **training-time assertion** rejecting rows whose `graded_at` is a bulk-batch date >> `game_date`.
- Fix `win_prob_loader.attach_win_prob` keying so production families map to real per-direction curves,
  not `_global` (which pools OVER+UNDER).
- Record in memory that the 2022-25 `prediction_accuracy` strata are leaked (done).
- **Gate:** reliability (ECE, monotone) on a *live* holdout before shipping pkls to GCS/image.

### P1.2 — Finish CLV closing-line capture ⭐ (season-open-BLOCKING)
`end:20→23` alone is insufficient. Cannot be backfilled — must be right before opening night.
- Add a **per-game T-30min snapshot** to the `betting_lines` workflow; redefine "closing" as the last
  snapshot with `minutes_before_tipoff ∈ [0,45]`.
- **Fix the retraction split-brain:** `clv_diverge_under_block` drops a morning pick from public JSON but
  keeps it `signal_status='active'` and graded as taken → the "drop if close moved ≥0.5 against it" rule
  is unmeasurable. Add explicit `signal_status='retracted_clv'` + grading reconciliation.
- Verify the 4:30 PM re-export reads a fresh (<90 min) processed snapshot; consider a second ~7 PM
  re-export scoped to the late slate (T-6h today).
- Confirm Odds API quota tolerates +2 runs/day on game days.

### P1.3 — Close the "COMPLETE-but-garbage" monitoring hole
